# Boundless Us 小程序资源交接文档

## 1. 交付目标

资源提供方最终提交一个 ZIP 压缩包。压缩包解压后只能包含一个顶层目录：`assets`。交付方只负责按本文档整理资源，不需要修改小程序代码。

后续程序以 `assets` 为资源根目录，读取固定文件、扫描固定目录，并解析 `cases.jsonl` 和 `resources.jsonl`。收到压缩包后，开发方会将 `assets` 解压到项目约定位置，再校验清单、解析本地路径并完成页面加载。资源提供方不得修改目录层级、固定文件名或 JSONL 字段名。

## 2. 完整目录结构

```text
assets/
├─ avator.png
├─ about.png
├─ home/
│  ├─ carousel-001.jpg
│  ├─ carousel-002.jpg
│  ├─ carousel-003.jpg
│  └─ background.png
├─ cases/
│  ├─ cases.jsonl
│  ├─ flag-football-intro/
│  │  ├─ thumbnail.jpg
│  │  ├─ carousel-001.jpg
│  │  ├─ carousel-002.jpg
│  │  ├─ lesson-plan.pdf
│  │  ├─ lesson-plan-page-001.jpg
│  │  ├─ lesson-plan-page-002.jpg
│  │  ├─ course.pdf
│  │  ├─ course-pdf-page-001.jpg
│  │  └─ course-pdf-page-002.jpg
│  └─ another-case-id/
│     └─ ...
└─ resources/
   ├─ resources.jsonl
   ├─ boundless-girls/
   │  ├─ image.jpg
   │  └─ thumbnail.png
   └─ another-resource-id/
      └─ ...
```

必须保留拼写 `avator.png`。后续程序将按该固定文件名读取首页与 About 共用头像。

除 `assets` 外，压缩包内不需要再提供 `manifest.json`、`source-files`、代码文件或额外的外层目录。

## 3. 通用命名规则

- 文件夹名称和业务 ID 只使用小写英文字母、数字和连字符 `-`。
- 不使用空格、中文、括号、下划线或其他特殊符号。
- 案例文件夹名称必须与 `cases.jsonl` 中的 `id` 完全一致。
- 资源文件夹名称必须与 `resources.jsonl` 中的 `id` 完全一致。
- 带顺序的图片使用三位数字编号：`001`、`002`、`003`。
- 照片优先使用 `.jpg`；需要透明背景时使用 `.png`。
- 文件名区分大小写，统一使用小写。
- JSONL 中的本地路径均相对于 `assets` 目录填写，使用 `/` 分隔。
- 路径不得包含盘符、反斜杠 `\`、绝对路径或 `../`。
- JSONL 中列出的文件扩展名必须与实际文件一致，不得出现清单写 `.jpg`、实际交付 `.png` 的情况。
- 同一条记录引用的图片、PDF 等文件必须全部放在该记录 ID 对应的文件夹内。

## 4. 首页和 About 资源

### 4.1 共用头像

固定路径：

```text
assets/avator.png
```

首页和 About 共用该文件。建议提供正方形透明 PNG，尺寸不低于 600 × 600 px。

### 4.2 首页轮播图

固定目录：`assets/home/`。

轮播图片按以下格式连续命名：

```text
carousel-001.jpg
carousel-002.jpg
carousel-003.jpg
...
```

轮播图数量不固定。程序按文件编号从小到大加载该目录下所有 `carousel-*.jpg`。编号必须从 `001` 开始并保持连续，不得跳号。

建议使用 16:9 横图，宽度 1200–1600 px，单张不超过 500 KB。

### 4.3 首页第三部分背景图

固定路径：

```text
assets/home/background.png
```

该图片显示在首页三个入口组件下方。建议使用透明 PNG 或主体位于中央的横图。

### 4.4 About 顶部图片

固定路径：

```text
assets/about.png
```

建议使用 16:9 横图，宽度 1200–1600 px。

## 5. JSONL 文件规则

JSONL 文件采用“一行一个 JSON 对象”的格式：

- 每行必须是完整、合法的 JSON 对象。
- 一个对象不能拆成多行。
- 行末不能添加逗号。
- 文件使用 UTF-8 编码。
- 不添加注释、标题行或 Markdown 标记。
- 空行会被忽略，但建议不要保留空行。
- 数组必须使用 JSON 数组格式，例如 `["身体自信","4-6年级"]`。
- 字符串内部出现双引号时必须写成 `\"`。

错误示例：

```json
{"id":"case-a"},
```

正确示例：

```json
{"id":"case-a","name":"案例 A"}
{"id":"case-b","name":"案例 B"}
```

## 6. Cases 交接规范

### 6.1 总表位置

所有案例信息统一写入：

```text
assets/cases/cases.jsonl
```

每个案例占一行。每条记录的 `id` 对应一个同名文件夹：`assets/cases/{id}/`。

### 6.2 每个案例的必填字段

| 字段 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `id` | string | 唯一 ID，同时作为案例文件夹名称 | `flag-football-intro` |
| `name` | string | 课程名称 | `腰旗橄榄球入门` |
| `teacher` | string | 上课老师或课程团队 | `李云翔老师` |
| `summary` | string | 列表页短介绍，建议 15–40 字 | `传球、跑动、配合……` |
| `description` | string | 详情页课程介绍 | 完整中文段落 |
| `categoryId` | string | 分类 ID | `body-confidence` |
| `gradeRange` | string | 适用年级 | `4-6年级` |
| `durationMinutes` | number | 课程时长，单位为分钟 | `90` |
| `tags` | string[] | 标签数组 | `["身体自信","4-6年级","90min"]` |
| `thumbnail` | string | 案例列表缩略图路径 | `cases/flag-football-intro/thumbnail.jpg` |
| `carousel` | string[] | 详情页轮播图路径数组 | `["cases/.../carousel-001.jpg"]` |
| `lessonPlan.file` | string | 教案 PDF 路径 | `cases/.../lesson-plan.pdf` |
| `lessonPlan.downloadUrl` | string | 教案 HTTPS 下载链接 | `https://example.com/lesson-plan.pdf` |
| `lessonPlan.previews` | string[] | 教案预览图路径数组 | `["cases/.../lesson-plan-page-001.jpg"]` |
| `coursePdf.downloadUrl` | string | 课程 PDF 的 HTTPS 下载链接 | `https://example.com/course.pdf` |

所有字段均为必填项。没有正式下载链接时，应先向项目负责人确认，不得填写无关网址。

字段名中的点表示嵌套对象。例如 `lessonPlan.file` 并不是 JSON 中的平铺键名，实际结构必须写为 `"lessonPlan":{"file":"...","downloadUrl":"...","previews":[...]}`。`coursePdf.downloadUrl` 同理。

### 6.3 案例文件夹固定内容

每个 `assets/cases/{id}` 文件夹必须包含：

```text
thumbnail.jpg
carousel-001.jpg
lesson-plan.pdf
lesson-plan-page-001.jpg
course.pdf
course-pdf-page-001.jpg
```

数量规则：

- 轮播图可以有多张，按 `carousel-001.jpg`、`carousel-002.jpg` 连续编号，并在 `carousel` 数组中按展示顺序列出。
- 教案预览可以有多页，按 `lesson-plan-page-001.jpg`、`lesson-plan-page-002.jpg` 连续编号，并在 `lessonPlan.previews` 数组中按页序列出。
- 课程 PDF 原文件固定命名为 `course.pdf`。由于 JSONL 只记录 `coursePdf.downloadUrl`，程序按固定路径 `cases/{id}/course.pdf` 查找该文件。
- 课程 PDF 预览图按 `course-pdf-page-001.jpg`、`course-pdf-page-002.jpg` 连续编号。程序扫描案例文件夹并按编号加载，不需要在 JSONL 中重复填写预览数组。
- 教案与课程 PDF 的预览编号都必须从 `001` 开始并保持连续。

### 6.4 `cases.jsonl` 单行示例

以下内容在实际文件中必须保持为一行：

```json
{"id":"flag-football-intro","name":"腰旗橄榄球入门","teacher":"李云翔老师","summary":"传球、跑动、配合——每个人都是不可或缺的一环","description":"无接触的腰旗橄榄球以扯腰旗代替身体撞倒，兼顾策略、体能与团队协作，是一项安全有趣的运动。","categoryId":"body-confidence","gradeRange":"4-6年级","durationMinutes":90,"tags":["身体自信","4-6年级","90min"],"thumbnail":"cases/flag-football-intro/thumbnail.jpg","carousel":["cases/flag-football-intro/carousel-001.jpg","cases/flag-football-intro/carousel-002.jpg"],"lessonPlan":{"file":"cases/flag-football-intro/lesson-plan.pdf","downloadUrl":"https://example.com/lesson-plan.pdf","previews":["cases/flag-football-intro/lesson-plan-page-001.jpg","cases/flag-football-intro/lesson-plan-page-002.jpg"]},"coursePdf":{"downloadUrl":"https://example.com/course.pdf"}}
```

## 7. Resources 交接规范

### 7.1 总表位置

所有资源信息统一写入：

```text
assets/resources/resources.jsonl
```

每个资源占一行。每条记录的 `id` 对应一个同名文件夹：`assets/resources/{id}/`。

Resources 与 Cases 采用相同的交接原则：一个总 JSONL 文件保存结构化信息，每条记录以 `id` 唯一标识，所有具体图片和文件都存放在 `resources/{id}/` 下，JSONL 只填写相对于 `assets` 的路径。

### 7.2 每个资源的必填字段

| 字段 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `id` | string | 唯一 ID，同时作为资源文件夹名称 | `boundless-girls` |
| `name` | string | 资源名称 | `撒开脚丫` |
| `organization` | string | 资源提供机构 | `耐克与公益伙伴` |
| `summary` | string | 列表页短介绍 | 简短中文介绍 |
| `description` | string | 完整介绍 | 完整中文段落 |
| `tags` | string[] | 标签数组 | `["运动","女孩成长"]` |
| `image` | string | 主图路径 | `resources/boundless-girls/image.jpg` |
| `thumbnail` | string | 缩略图或 Logo 路径 | `resources/boundless-girls/thumbnail.png` |
| `link` | string 或 null | 已核实的 HTTPS 网址；没有时填 `null` | `https://example.com` |

### 7.3 资源文件夹固定内容

每个 `assets/resources/{id}` 文件夹至少包含：

```text
image.jpg
thumbnail.png
```

`image.jpg` 用作资源主图，`thumbnail.png` 用作缩略图或 Logo。确需使用其他图片格式时，必须同时修改 `resources.jsonl` 中的路径和扩展名。

### 7.4 `resources.jsonl` 单行示例

```json
{"id":"boundless-girls","name":"撒开脚丫","organization":"耐克与公益伙伴","summary":"帮助乡村女孩通过运动变得更自信、更快乐。","description":"填写经过确认的完整项目介绍。","tags":["运动","女孩成长"],"image":"resources/boundless-girls/image.jpg","thumbnail":"resources/boundless-girls/thumbnail.png","link":"https://example.com"}
```

## 8. 图片和文件规格

| 用途 | 建议尺寸与比例 | 建议格式 |
| --- | --- | --- |
| 首页轮播图 | 16:9，宽 1200–1600 px | JPG |
| 首页背景图 | 主体居中，适合横向区域 | PNG |
| 共用头像 | 正方形，不低于 600 × 600 px | 透明 PNG |
| About 顶部图 | 16:9，宽 1200–1600 px | JPG/PNG |
| 案例轮播图、案例缩略图 | 16:9 或 3:2 | JPG |
| 教案与课程 PDF 预览图 | 保持原页面比例，宽约 1200 px | JPG |
| 资源主图 | 16:9 或 3:2 | JPG |
| 资源缩略图或 Logo | 正方形 | 透明 PNG 优先 |
| 教案和课程文件 | 可正常打开的完整文件 | PDF |

建议单张图片不超过 500 KB。图片不得包含手机状态栏、微信胶囊按钮、底部导航或设计稿手机外框。

## 9. 压缩包要求

压缩包名称建议使用：`boundless-us-assets-YYYYMMDD.zip`。

正确结构：

```text
boundless-us-assets-20261015.zip
└─ assets/
```

错误结构：

```text
boundless-us-assets-20261015.zip
└─ 张三-最终版/
   └─ assets/
```

压缩包中不要包含 `__MACOSX`、`.DS_Store`、`Thumbs.db`、临时文件、重复文件或设计源文件。

## 11. 开发方接收与解析约定

开发方收到 ZIP 后按以下顺序处理，交付方无需执行这些开发步骤：

1. 解压并确认压缩包顶层只有 `assets/`。
2. 检查固定文件 `avator.png`、`about.png` 以及 `home/` 是否存在。
3. 逐行解析 `cases/cases.jsonl` 和 `resources/resources.jsonl`；任意一行 JSON 无效时停止导入并报告行号。
4. 校验 `id` 是否唯一，并确认每个 `id` 都存在同名目录。
5. 将 JSONL 内的相对路径拼接到 `assets/` 根目录，并检查引用文件是否真实存在。
6. 首页轮播图按文件名编号排序；案例轮播图和教案预览图严格按 JSONL 数组顺序展示。
7. 校验通过后，再将清单内容转换为小程序使用的数据结构并加载本地资源。

开发方解析时不会根据相似文件名自动猜测或纠正路径。因此，目录名、文件名、扩展名和 JSONL 路径必须完全一致。
